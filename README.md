# Wealth Map

A retirement-readiness application with a browser experience, application service, and persisted plan data, based on the product requirements and wireframe documents in [planning/](planning/).

## Run locally

The current repository contains the browser UI and deterministic calculation baseline. The first release must run with the application service and database so users can authenticate and return to saved plans. Opening `index.html` directly is supported only for UI inspection during development, not as the released deployment model.

```text
python -m http.server 8000
```

Then open `http://localhost:8000`.

## Release deployment

The released browser experience must be deployed with the application service and database. The deployment must support authenticated plan access, server-side validation, persisted plan versions, and secure backups. Hosting the current static baseline on GitHub Pages is not sufficient for the first release.

## Product behavior

- Six navigable views: Readiness, Plan Setup, Assets, Income & Expenses, Wealth Timeline, and Recommendations.
- Editable plan-setup, asset, income, expense, and projection-assumption fields with core inputs immediately visible and advanced tax settings in a collapsible section.
- The Plan Setup page shows personal details, projection assumptions, tax filing status, state, Social Security benefit settings, and Social Security claim age by default. New plans default to Automatically estimate for the Social Security benefit at Full Retirement Age (67), calculated from current earnings. Users can switch to Enter manually to provide their own estimate from a Social Security statement. The claim age input (62-70, default 67) sits next to the benefit mode so the two fields are edited together. Advanced Tax & Retirement Settings (federal deduction, state tax rate, taxable gains rate, pre-tax withdrawal rate, annual Roth conversion, Social Security taxability, RMD start age, NIIT threshold, IRMAA settings, and Cash Reserve (Years of Spending), which controls how many years of retirement spending the model attempts to maintain in cash, with an info icon explaining the brokerage-to-cash refill behavior) are grouped in a collapsed section that users can expand as needed. Most users can leave advanced settings at their defaults.
- The default sample profile uses Florida with a 0% state income tax rate, a simpler and more realistic starting point since Florida has no state income tax. Users may change the state and state income tax rate at any time; percentage fields such as State Income Tax Rate always display a clean, rounded percentage (for example `4.4`, not `4.4000000000000004`) regardless of the underlying stored value.
- Required Plan Setup inputs are enforced with blocking validation and non-blocking financial warnings before the retirement model runs.
- An editable year-by-year wealth timeline from the current age through life expectancy, with per-year overrides that fall back to the modeled value when left blank.
- Shared working state with live recalculation.
- Reset-to-sample behavior, including any wealth-timeline overrides.
- Social Security benefit estimation and claim age are first-class Plan Setup inputs: new plans default to an automatic Full Retirement Age (67) benefit estimate based on current earnings, while allowing manual benefit entry for greater accuracy. The selected claim age (62-70) determines both the reduced or increased benefit paid and the age at which Social Security income, taxation, and withdrawal offsets begin in the Timeline. A model-generated Roth conversion schedule remains on by default using the same retirement engine.
- Timeline-first strategy review: users can optionally switch Social Security to a model-recommended claiming age (searching 62-70 for the age that keeps the plan solvent longest) or adjust the Roth conversion strategy directly on the Timeline page; these remain adjustments layered on top of the same retirement engine, not prerequisite inputs. Benefit source (automatically estimated vs. manually entered in Plan Setup) and claiming age source (Plan Setup choice vs. Timeline model recommendation) remain clearly distinct.
- Transparent retirement projection, funding gap, Timeline-based Safe Spending estimate, heuristic score, and lightweight tax-aware estimate.
- Readiness report preview with a concise four-page Retirement Plan Summary that can be printed or saved as a PDF, using current recommendations and timeline milestones.
- A compact retirement-milestone layer on the Timeline page that highlights the largest retirement transitions already represented in the model, such as retirement start, Social Security start, first RMD, first IRMAA year, peak portfolio value, and depletion.
- Milestone-based portfolio composition snapshots on the Timeline page show dollar amounts and shares for cash, taxable brokerage, tax-deferred, and Roth assets at the current year, retirement start, first RMD year, and life expectancy. The snapshots keep composition in the retirement workbench and surface tax diversification, RMD exposure, withdrawal sources, and liquidity without requiring a separate investment-performance graph.
- Readiness metric tooltips that provide plain-language help for the score, Safe Spending, and the tax-aware summary values without adding permanent explanatory text to the page.
- Editable federal deduction, state tax, taxable gains, pre-tax withdrawal, Roth conversion, Social Security, NIIT threshold, retirement cash-reserve target, IRMAA, and RMD start age assumptions.
- Rule-based recommendations with visible triggers and rationale, including two that come directly from the wealth timeline (a projected shortfall year and a projected IRMAA year).
- Responsive expanded desktop sidebar and collapsed mobile drawer.

## UX and disclaimer approach

WealthMap is a finished educational planning tool for retirement planning:

- A single, subtle global disclaimer appears once, in the application footer: "WealthMap is an educational retirement planning tool, not a tax, legal, or investment advisor. Consult qualified professionals before making important financial decisions." It is not repeated on individual pages, cards, or recommendations.
- Model-generated Social Security and Roth conversion strategies are labeled "Model-recommended" with a compact tooltip explaining that they use the plan's current assumptions; they are illustrative planning outputs, not instructions to execute a transaction.
- Validation errors, cross-field errors, and non-blocking financial warnings (cash-flow, contribution affordability, projected depletion, funding shortfall) remain fully in place and are always shown next to the relevant field or metric.
- Notices that only explained where a setting used to live, that a feature recently moved, or how the model is implemented internally have been removed; the current page layout and field labels communicate the plan structure directly. These were temporary migration aids, not part of the permanent product experience.

## Calculation model

The full model is documented in [planning/calculation-model.md](planning/calculation-model.md). The headline rules are:

- Financial assets include taxable brokerage, 401(k), Traditional IRA, Roth IRA, and cash. Real estate is included only in total assets, never in the retirement portfolio projection.
- Gross income is salary plus other annual income. The employee 401(k) contribution rate and the Traditional IRA annual dollar contribution both reduce the simplified tax base; Roth IRA is a fixed annual dollar contribution that does not change taxable income. The displayed annual surplus reflects employee contributions and expenses, while employer match remains separate.
- Traditional IRA and Roth IRA contributions are entered as fixed annual dollar amounts rather than percentages of income, matching how most users think about IRA funding ("I contribute $7,000 per year"). An optional "Use current IRS max" button next to each field fills in the illustrative current-year IRA limit ($7,000 under age 50, $8,000 at 50+) without introducing separate contribution logic. Plan Setup validation blocks negative, non-numeric, or non-finite IRA contribution amounts, and shows non-blocking warnings when contributions exceed available income, are unusually high relative to income, or would create a negative annual cash-flow position.
- Brokerage and Cash are no longer calculated as a percentage of after-tax income. Instead, WealthMap first computes **Available Annual Savings** = after-tax income − current annual expenses − the Roth IRA annual contribution (floored at zero, so it never goes negative). `Brokerage Allocation %` and `Cash Allocation %` then split that Available Annual Savings pool between a taxable brokerage account and cash, and must total 100%; Plan Setup blocks any combination that doesn't ("Brokerage and Cash allocations must total 100%."). Because they only allocate an already-nonnegative pool, Brokerage and Cash contributions can never create additional negative cash flow. Savings Rate, Employee Savings, Total Retirement Contributions, the Retirement Health Score, projected assets, the funding gap, the Wealth Timeline, and portfolio sustainability all use the resulting dollar amounts automatically.
- Profiles saved before this change may still contain the legacy `contributionRates.traditionalIra`/`contributionRates.rothIra` percentages, or the legacy `contributionRates.brokerage`/`contributionRates.cash` percentage-of-income rates. The model migrates both automatically the first time it calculates: IRA percentages are reconstructed into fixed annual dollar amounts using the profile's own income and tax assumptions, and the Brokerage/Cash percentages are converted into an equivalent `savingsAllocation.brokerage`/`savingsAllocation.cash` split (preserving their relative proportion) before the legacy fields are dropped. No user action is required, and existing plans continue to load and calculate successfully.
- The projection is expressed in real dollars. The entered nominal return is converted to a real return using `(1 + nominal return) / (1 + inflation) - 1`. Each account receives its own end-of-year contribution. An employer 401(k) match is calculated from the employee 401(k) contribution, subject to the editable salary-percentage cap. Brokerage gains are taxed once per year at the editable taxable-gains rate plus a simplified 3.8% net investment income tax (NIIT) above an editable MAGI threshold, instead of compounding pre-tax.
- At the beginning of the target retirement year, tax-deferred balances are reduced by the editable pre-tax withdrawal tax rate to produce after-tax projected assets. Readiness `Required Assets` is the minimum after-tax target-year portfolio that survives the full Timeline horizon through life expectancy, found by rerunning the same retirement engine at scaled target-year balances. This keeps the Projected Assets and Required Assets comparison aligned with long-term sustainability rather than a single-year withdrawal-rate snapshot. Required minimum distributions use an illustrative IRS Uniform Lifetime Table divisor rather than a flat rate.
- The Wealth Timeline page projects every age from the current age through life expectancy using the same rules, applies the Plan Setup Social Security claim age (or a model-recommended claim age when that Timeline strategy is selected) and a Roth conversion plan by default, lets the user override any single year (return, income, spending, or a one-time withdrawal), and applies a sequence-of-returns cash-reserve buffer during retirement. Social Security income, its taxation, and its offset to required withdrawals are zero before the claim age and active at and after it. The Timeline remains the source of truth for the eventual plan, while user overrides are treated as local adjustments rather than required planning inputs. The Timeline also shows a read-only Social Security claiming-age comparison for ages 62-70 and a "Social Security begins" milestone at the selected claim age.
- The Timeline presents portfolio composition as milestone snapshots rather than a standalone graph. Each snapshot uses the row's ending account balances and shows cash, taxable brokerage, tax-deferred, and Roth dollars plus their share of financial assets. Comparing the current year, retirement start, first RMD year, and life expectancy helps users see tax diversification and how available withdrawal sources change. The accompanying planning note calls out active RMD exposure, a tax-deferred majority, or a small cash reserve where the modeled mix makes those decisions relevant. Real estate remains excluded from these spendable portfolio snapshots.
- On the Readiness page, `Projected Social Security Tax` is the cumulative projected Social Security taxation across all retired rows from the existing `buildTimelineRows()` engine through life expectancy. It sums each row's modeled `socialSecurityTax` value rather than showing only a single year's tax or only the tax at retirement. The total is derived from the application's existing retirement projection engine, so retirement and life-expectancy ages, RMDs, withdrawals, the taxable Social Security assumption, income and tax assumptions, timeline overrides, and any future model enhancements that affect taxation of benefits can change it. The value is a high-level illustrative estimate of cumulative tax paid on Social Security benefits across retirement; use the Timeline for annual detail and timing.
- On the Readiness page, `Projected RMD` is the cumulative sum of annual RMD values from the first modeled RMD year through life expectancy. It summarizes the overall future mandatory-distribution exposure rather than showing one year's RMD or only the RMD at retirement. The value is derived from the existing Wealth Timeline projection, so current balances, contributions, employer match, Roth conversions, retirement and RMD start ages, life expectancy, income, spending, return, inflation, timeline overrides, and withdrawal behavior can influence it. The Timeline remains the detailed annual view, and the metric uses the same projection basis as the model.
- On the Readiness page, `Projected NIIT` is the cumulative modeled NIIT exposure from the current age through life expectancy, including both accumulation and retirement years. It is summed from annual NIIT values produced by the existing Wealth Timeline retirement engine and uses the same brokerage-growth, income, tax-assumption, and withdrawal logic as the rest of the model. Asset balances, brokerage gains, retirement age, life expectancy, timeline overrides, and future model changes can therefore affect it. It is a high-level illustrative estimate, not an official tax liability or advice; the Timeline provides annual context.
- On the Readiness page, `Projected IRMAA` is the cumulative modeled Medicare income-related surcharge across retired timeline years through life expectancy. It is summed from the annual `irmaa` values produced by the existing Wealth Timeline engine, rather than showing a single year or only the surcharge at retirement. The total is an illustrative estimate influenced by projected balances, RMDs, Social Security taxability, retirement and life-expectancy ages, IRMAA threshold and surcharge assumptions, spending, returns, inflation, timeline overrides, withdrawal behavior, and future model changes. The Timeline remains the detailed annual view and the source for tracing timing and amounts.
- The Retirement Health Score is a 0-100 heuristic: 60% long-horizon funding progress, 25% savings-rate progress toward 20%, and 15% timing progress, minus a penalty of up to 20 points when the wealth timeline projects asset depletion before life expectancy. A plan meeting the target age receives full timing credit; a later expected age loses credit linearly through life expectancy. The Readiness page and Timeline use the same retirement engine and assumptions; the Timeline provides annual detail.
- Readiness `Safe Spending` is the maximum annual retirement spending goal that remains solvent through life expectancy when the same Timeline engine is rerun with candidate spending levels. It incorporates the model's returns, taxes, Social Security, RMDs, IRMAA, NIIT, Roth conversions, cash-reserve behavior, withdrawals, and timeline overrides. The Safe Withdrawal Rate remains an editable assumption for required-assets calculations; it is not a substitute for this horizon-based spending result.
- The Retirement Health Score is the primary Readiness summary indicator. It combines funding progress, savings, retirement timing, and the Timeline's long-term sustainability result. It updates automatically as planning assumptions change and is intended as a planning aid, not a guarantee, probability, or prediction of retirement outcomes.
- Plan Setup validation enforces the minimum required inputs for the projection engine: current age, target retirement age, life expectancy, expected annual return, inflation rate, and retirement spending goal. Other values such as name, state, social security benefit, Roth conversion, and IRMAA surcharge may remain optional when zero is meaningful or the model supports an empty value.
- Blocking validation errors stop the model from running while the user fixes contradictory or invalid values, and the last valid projection remains visible until the form is corrected. Warning states are non-blocking and highlight financially unusual but technically valid conditions such as high contribution burdens, low or zero spending, or expected real returns below inflation.
- Age rules are enforced on the Plan Setup page: current age and target retirement age must be between 0 and 120, target retirement age cannot be earlier than current age, life expectancy must be later than the target retirement age, and the RMD start age must also remain within the supported range. Monetary inputs cannot be negative, percentage inputs must stay between 0% and 100%, and malformed numeric input is rejected before it reaches the calculation engine.
- Readiness metric explanations are intentionally lightweight and contextual. Each tooltip is meant to help users interpret what a metric means in retirement planning terms rather than explain the exact code path or model internals. The score, Safe Spending, projected RMD, projected NIIT, projected IRMAA, and projected Social Security tax each have a summary tooltip that uses clear, plain-language phrasing and keeps the main Readiness page uncluttered. The tooltip content focuses on practical meaning: whether the number is cumulative or annual, what the term means in plain language, and how the value should be used in a planning conversation.
- The Timeline milestone layer is built from the same annual timeline rows used elsewhere in the app. It does not add a separate retirement model; instead it summarizes important events already represented by the projection engine, such as the first retirement year, the start of Social Security income, the first modeled RMD, the first IRMAA year, the projected portfolio peak, and projected depletion. Any change to returns, spending, tax assumptions, RMD age, Social Security, cash-reserve behavior, or per-year timeline overrides will update the milestone layer automatically because it is fed directly from the same model output.

## Calculation boundary

The application uses simplified calculations. It includes lightweight estimates for progressive federal brackets, state income tax, taxable gains, NIIT, pre-tax withdrawal tax, Roth conversion tax, Social Security taxation and claiming-age comparison, IRMAA, and RMDs. These are illustrative planning estimates, not official tax calculations.

Social Security defaults to automatically estimating the Full Retirement Age (67) annual benefit from current earnings, presenting a read-only estimate on Plan Setup. Users can switch to manual entry to enter their benefit from their Social Security statement for higher precision. Social Security claim age defaults to Full Retirement Age (67) on Plan Setup; users may optionally switch Social Security to a model-recommended claiming age on the Timeline page. Existing user-entered benefits are preserved, and legacy profiles without a meaningful benefit automatically migrate to automatic estimation. Roth conversions remain model-generated by default, and users may switch that strategy to Manual on the Timeline page when they want to replace the recommendation with their own assumption.

### Social Security benefit modes and claim age

- **Benefit mode (Plan Setup):** Determines the baseline Full Retirement Age (67) benefit.
  - _Automatically estimate (default):_ Computes an illustrative Full Retirement Age benefit based on current earnings and updates dynamically when salary changes. The value is presented read-only with concise contextual help.
  - _Enter manually:_ Displays an editable currency input for users who have their official Social Security statement estimate. Entered values are preserved even if the user temporarily toggles modes.
- **Claim age (Plan Setup):** The selected claim age (62-70, default 67) adjusts the Full Retirement Age benefit via the early/delayed claiming formula (5/9% per month for first 36 months early, 5/12% per month thereafter; 2/3% per month / 8% per year delayed after 67).
- **Claiming strategy (Timeline):** Users can either keep their Plan Setup claim age or select _Model-recommended claiming age_ to let the engine find the claim age (62-70) that maximizes solvency.
- The claim-age-adjusted benefit, not the raw Full Retirement Age amount, is what the Timeline, retirement readiness, and tax calculations use.
- Before the claim age, modeled Social Security income, Social Security taxation, and the Social Security offset to required withdrawals are all zero; at and after the claim age, the adjusted benefit, its taxation, and its reduction of required withdrawals are all active.
- Required assets, projected assets, funding gap/surplus, expected retirement age, Safe Spending, projected Social Security tax, and the Retirement Health Score all respond automatically because they are derived from the same Timeline rows; no separate scoring adjustment exists for claim age.

The Retirement Health Score is a heuristic based on funding progress, savings rate, and retirement timing. It is not a probability of retirement success or financial advice.

The app models only the real-dollar projection basis. It does not model payroll taxes, itemized deductions, tax credits, capital-gain holding periods, tax-law changes, inflation-adjusted tax brackets, Social Security claiming optimization, full RMD cash-flow alerting, IRS contribution limits, eligibility rules, vesting, salary growth, employer-match changes, spousal Social Security benefits, or an optimized Roth-conversion strategy.
